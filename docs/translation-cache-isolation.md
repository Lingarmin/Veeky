# 译文缓存隔离与历史迁移

本次修复对应上架审查第 2 项：译文缓存未按安装实例隔离。

## 隔离规则

- 新译文的缓存键与数据库唯一约束包含 `installation_id`，同一安装实例可复用自己的译文。
- Worker 写入、结果 API 读取、任务中断恢复和 X 视频结果复用均检查安装归属。
- 新任务不能使用其他安装实例的译文，也不能复用归属未知的旧共享译文。
- 安装身份来自已认证的任务或请求，不接受用户指定译文归属。

## 旧历史保留

迁移 `0009_translation_ownership` 不删除任务、摘要、字幕或译文。

旧共享译文保持 `installation_id = NULL`，不推断生成者。迁移只为原有已完成历史（以及翻译失败的部分结果）建立 `legacy_translation_id`：内容、源语言、目标语言、字幕版本、provider、模型及 endpoint 指纹必须唯一且完全匹配。缺少完整配置或匹配存在歧义的记录不猜测关联。

读取旧历史时必须先验证任务归属，然后读取该任务明确关联的旧译文。新任务不写入此关联；后来生成的安装专属译文也不会替换旧历史显示的译文。旧 endpoint 仅用于核对指纹，不发起网络请求、不重新允许中转服务。

## 部署与回滚

1. 先运行后端测试并构建 API、Worker、Scheduler 镜像。
2. 确认没有正在执行的分析任务，停止接收新任务并停止上述三个服务，避免旧 Worker 在新表结构中继续写无归属译文。
3. 使用 `pg_dump -Fc` 保存数据库备份到仓库外的受限目录；备份可能含用户历史和加密凭据，不能提交 Git。
4. 启动新服务，由 API 执行 Alembic 迁移。核对健康检查、Worker、迁移版本及任务、结果、译文和安装身份数量。
5. 本次不更换浏览器扩展安装目录、不清除插件存储。

一旦写入新的安装专属译文，降级迁移会主动拒绝执行，避免将不同用户译文合并或丢弃。需要回滚时应停服并按备份恢复流程处理；恢复旧备份会失去备份之后的数据，必须先另存当前数据库。不要直接删除数据库或 Docker 卷。

## 验证范围

- 两个安装实例处理同一字幕、模型和 endpoint，分别调用自己的翻译服务并保存不同译文。
- 同实例缓存命中；缺少安装身份时拒绝访问缓存。
- 结果 API 不读取外部归属或无绑定旧译文，其他安装实例不能访问任务结果。
- 精确绑定旧历史仍能显示原译文，后续新缓存不覆盖它。
- X 新任务不会仅因旧历史摘要存在而跳过译文生成；中断恢复检查同一隔离条件。
- PostgreSQL 迁移保留 YouTube / X 历史；允许不同安装实例拥有相同缓存参数，但拒绝同实例重复键。

这些测试使用模拟 LLM，不调用收费模型。

## 本地验证记录（2026-10-27）

后端测试共 706 项通过。主本地服务升级至 `0009_translation_ownership` 前后，均保留 16 个任务、7 条摘要结果、6 条译文和 2 个安装身份。6 个历史任务获得明确旧译文关联；原有 8 份可读取结果（含部分失败结果）的序列化内容 SHA-256 完全一致。数据库备份保存在仓库外的受限目录。
