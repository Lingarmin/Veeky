# 分析历史记录设计

## 目标

插件保存并展示所有成功完成的分析记录。用户可以直接打开旧结果，同一视频重新分析时新增一个版本，不覆盖原记录。

## 范围

本次包含历史列表、历史结果查看、当前视频自动命中最新结果，以及强制重新分析生成新版本。

本次不包含删除历史、重命名记录、搜索、收藏、跨设备账号同步和失败任务管理。

## 数据来源

历史记录使用现有 PostgreSQL 数据：

- `analysis_jobs` 保存每次分析任务、视频 ID、语言、状态和完成时间。
- `analysis_results` 保存摘要、章节和精彩片段。
- `videos` 保存 YouTube 标题、视频时长和链接。
- 字幕与翻译继续使用现有缓存表。

历史查询只返回 `status = completed` 且存在 `analysis_results` 的任务。API 不返回任务中保存的 LLM API Key。

不增加数据库表或字段，也不需要迁移现有数据。

## 历史列表 API

新增接口：

```http
GET /v1/analyses/history?videoId=<optional>&limit=20&offset=0
```

结果按 `completed_at DESC, id DESC` 排序。接口读取 `limit + 1` 条记录，用于计算 `hasMore`，避免额外的总数查询。

响应结构：

```json
{
  "items": [
    {
      "jobId": "uuid",
      "videoId": "aircAruvnKk",
      "videoTitle": "But what is a neural network?",
      "durationMs": 1142000,
      "sourceLanguage": "en",
      "targetLanguage": "zh-Hans",
      "completedAt": "2026-08-11T09:40:00Z",
      "modelName": "deepseek",
      "modelVersion": "deepseek-v4-flash"
    }
  ],
  "hasMore": false
}
```

`videoId` 用于查找当前视频最新完成记录。`limit` 最小为 1，最大为 100。`offset` 不能小于 0。

## 创建新分析版本

`POST /v1/analyses` 请求增加 `force`，默认值为 `false`。

- `force=false` 保持现有缓存行为，相同分析条件复用已完成任务。
- `force=true` 在标准缓存键后增加随机运行标识，创建新的 `AnalysisJob`。
- 强制重新分析可以复用字幕和翻译缓存，但必须重新生成摘要。
- 新任务完成后成为新的历史记录。
- 新任务失败时不出现在历史列表，旧记录不受影响。

前端进入处理状态后禁用重复提交。API 将每次明确的 `force=true` 请求视为一次新的分析版本。

## 侧边栏导航

### 历史入口

插件右上角增加 Lucide `History` 图标按钮，悬浮提示为“历史记录”。入口与设置、刷新按钮保持同一工具栏样式。

### 历史列表

历史页首次加载 20 条记录。每条记录显示：

- 主标题：YouTube 视频标题。
- 次标题：`视频时长 12:34 · 2026-08-11 17:40`。

点击记录后调用现有结果接口获取完整摘要和字幕，不检查 YouTube 字幕，也不调用 LLM。列表底部在 `hasMore=true` 时显示“加载更多”。空列表显示“还没有分析记录”。

### 历史结果

从历史列表打开的结果沿用现有概览和逐字稿界面。页面提供返回历史列表按钮。点击时间戳时：

- 当前标签页是同一视频，直接控制播放器进度。
- 当前标签页不是该视频，打开对应 YouTube 视频并定位时间。

### 当前视频自动命中

侧边栏打开后按以下优先级处理：

1. 当前标签页登记了未结束的分析任务，恢复轮询并显示处理进度。
2. 当前视频存在已完成记录，自动打开最新完成的结果。
3. 当前视频没有已完成记录，显示现有的视频选择和字幕检查界面。

已登记任务如果失败，前端查询该视频的最新完成记录。有旧记录时打开旧记录，没有旧记录时显示失败信息。

## 重新分析

完整结果页显示“重新分析”按钮，包括自动命中的结果和历史结果。

点击后执行：

1. 检查用户当前选择的 LLM 配置是否完整。
2. 使用结果中的 `videoId`、`videoTitle`、`sourceLanguage` 和 `targetLanguage` 创建分析。
3. 请求传递 `force=true`。
4. 如果当前标签页不是该视频，先打开该视频。
5. 登记新 jobId 并显示处理进度。
6. 完成后显示新结果，历史列表新增一条记录。

如果视频字幕已不可读取或 LLM 配置失效，显示现有的可执行错误提示，旧结果仍可通过历史记录查看。

## 前端状态

侧边栏增加 `history` 页面状态和以下数据：

- 历史记录数组。
- 分页 offset 与 `hasMore`。
- 历史加载错误。
- 当前结果是否从历史页进入，用于决定返回按钮行为。

历史页请求失败时保留重试入口，不清空当前已经展示的历史项。

## 影响范围

需要修改：

- `api/app/api/analyses.py`：历史响应模型、列表接口、`force` 创建逻辑。
- `api/tests/test_analyses_api.py`：历史过滤、排序、分页和强制创建测试。
- `extension/src/shared/types.ts`：历史记录类型和 `force` 请求字段。
- `extension/src/sidepanel/api.ts`：历史列表 API。
- `extension/src/sidepanel/App.tsx`：初始化自动命中、历史导航、列表和重新分析。
- `extension/src/sidepanel/styles.css`：历史列表布局和状态样式。
- `extension/tests/App.test.tsx`：自动打开、列表、返回和重新分析测试。
- `extension/tests-e2e/sidepanel.spec.ts`：关键历史流程回归。

不修改 `manifest.json`、Service Worker 消息协议和数据库结构。

## 风险控制

- 当前视频自动查询增加一次本地 API 请求，不触发字幕或 LLM 服务。
- 历史列表不包含 LLM 配置，避免泄露 API Key。
- 强制重新分析使用新缓存键，旧任务和结果不会被更新。
- 相同视频的多个版本使用完成时间区分。
- 历史只查询完成任务，进行中和失败任务不会污染列表。

## 验收标准

- 右上角可以进入和退出历史列表。
- 历史只展示成功完成的任务，并按完成时间倒序排列。
- 每条记录显示视频标题、视频时长和分析完成时间。
- 点击历史记录直接显示已有概览和逐字稿，不检查字幕，不调用 LLM。
- 当前 YouTube 视频存在历史时，侧边栏自动打开最新完成结果。
- 点击重新分析会生成新 jobId，完成后新增历史记录，旧记录内容不变。
- 重新分析失败不会删除或覆盖旧记录。
- 历史分页、空状态和加载失败状态可正常操作。
- 现有字幕检查、翻译、摘要、时间跳转和 LLM 配置功能保持正常。

## 回退

本功能没有数据迁移。回退 API 的历史接口、`force` 分支和扩展历史视图即可恢复旧行为。已经生成的额外完成任务仍是有效分析记录，不需要清理。
