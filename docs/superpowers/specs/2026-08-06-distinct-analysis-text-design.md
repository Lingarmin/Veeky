# 摘要标题与说明差异化设计

## 目标

让“章节与重点”和“值得看的片段”中的标题、说明与字幕摘录各自承担不同职责，避免同一句文字连续出现。

## 当前问题

分析提示词只要求模型返回 `title`、`summary` 和摘录，没有解释字段之间的内容差异。兼容 DeepSeek 和 Kimi 非标准返回时，后端还会用同一段文字补齐缺失字段。前端随后无条件展示全部字段，因此一个片段可能连续出现三到四次相同内容。

## 内容规则

### 章节与重点

- `title` 是简短的章节主题，便于快速浏览。
- `summary` 说明这一章具体讲了什么、采用了什么方法或得出了什么结论。
- `summary` 不能复述 `title`，忽略标点、空格和大小写后也不能相同。

示例：

- 标题：`使用 Figma Make 生成 UI 页面`
- 说明：`作者将情绪板中的视觉方向转成提示词，并演示了首页界面的生成过程。`

### 值得看的片段

- `title` 概括该片段的观看价值或核心观点。
- `summary` 解释为什么值得看，补充操作、证据、结论或适用场景。
- `translated_excerpt` 和 `original_excerpt` 是字幕原话，不承担概括职责。
- `summary` 不能复述 `title`，也不应直接复制字幕摘录。

示例：

- 标题：`用真实产品截图建立设计方向`
- 说明：`这一段展示了如何从 Mobbin 收集参考界面，并把可复用的布局和视觉细节整理进情绪板。`
- 摘录：视频中与该结论对应的字幕原话。

## 实现方案

### 生成约束

更新 LLM 分析提示词，明确每个字段的职责，并要求标题与说明提供互补信息。提示词包含一个正确示例和一个禁止重复的反例。分段分析与普通分析使用同一套规则。

### 后端质量检查

后端在结构校验后比较每个章节和片段的 `title` 与 `summary`。比较前移除空白和标点并统一大小写。如果内容相同，当前分析响应视为不合格，服务会重新请求模型。重试次数保持现有配置，不增加额外网络请求上限。

对只返回 `text`、`quote` 或 `description` 的兼容响应，后端仍可补齐结构，但不会把这种降级数据误判为高质量结果。模型连续无法给出差异化内容时，保留现有失败处理，不写入新的低质量摘要。

### 前端展示兜底

前端渲染前对同一条目内的文字进行轻量归一化比较：

- `summary` 与 `title` 相同则不显示 `summary`。
- 译文摘录与已显示的标题或说明相同则不重复显示。
- 原文摘录与其他字段相同则不重复显示。

这项兜底让旧分析结果在重新分析前也不会连续展示相同文字。它只影响显示，不修改已保存的数据。

## 数据与接口

不修改数据库、API 字段和扩展共享类型。`title`、`summary`、`translated_excerpt` 和 `original_excerpt` 保持现有结构，因此不需要迁移数据。

## 验收标准

- 新生成的每个章节，其 `title` 与 `summary` 在归一化比较后不同。
- 新生成的每个值得看片段，其 `title` 与 `summary` 在归一化比较后不同。
- 同一条目不会连续展示相同的标题、说明或摘录。
- 旧分析结果即使包含重复字段，侧边栏也只展示一次相同内容。
- 时间戳跳转、逐字稿、翻译和任务状态保持原有行为。
- DeepSeek 与 Kimi 的现有兼容格式继续可解析。

## 测试范围

- API 单元测试覆盖章节标题与说明重复、片段标题与说明重复、标点和空格差异造成的伪差异。
- LLM 提示词测试确认差异化规则随请求发送。
- 扩展组件测试覆盖章节和片段的重复文字隐藏，以及内容不同的正常展示。
- 运行 API、扩展、类型检查和构建回归。

## 风险与回退

更严格的质量检查可能让输出能力较弱的模型多请求一次。现有最多三次的限制可以控制成本和等待时间。若实际失败率明显增加，可以回退后端拒绝规则，仅保留提示词和前端去重。

本次修改不涉及数据库迁移、Manifest 权限或 Service Worker 行为。回退时恢复分析服务和侧边栏组件的对应改动即可。
