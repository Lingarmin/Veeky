# YouTube 视频预览工具 MVP：产品需求与技术实施方案

**状态：** MVP 已实现，待内部联调

## 1. 产品定义

这是一个 Chrome 扩展。用户在 YouTube 视频详情页打开扩展后，可先查看视频的中文概览、章节、重点时间点以及带时间戳的原文和译文，再决定是否观看完整视频。

MVP 只支持 YouTube 已公开并且实际可读取的字幕。翻译先使用 LibreTranslate，供开发和内部测试使用；翻译模块保留统一接口，后续可切换到 LLM 服务。这里的 LLM 替换仅针对翻译，不改变摘要与章节生成模块。

## 2. 范围与边界

### 2.1 MVP 包含

1. 在 YouTube 视频页发起分析。
2. 检测并选择可读取字幕轨道，人工字幕优先，自动字幕作为备选。
3. 保存句段级时间戳、原始字幕和译文。
4. 生成一句话概览、摘要、章节和重点片段。
5. 将每项结果关联回 YouTube 的播放时间，支持点击跳转。
6. 在分析发起的 YouTube 标签页显示 Side Panel。
7. 缓存同一视频、源语言和目标语言的结果。

### 2.2 MVP 不包含

1. 无公开字幕视频的音频下载和语音转录。
2. 下载视频并用 FFmpeg 生成真实关键帧。
3. 视频内问答、账户体系、支付、分享和导出。
4. 承诺支持私人、受限、地区限制或必须登录的视频。

原始需求中的“重点截图与文字并排”分两阶段处理：MVP 先展示重点文字卡片和可跳转时间点，第二阶段接入媒体处理后再展示真实视频关键帧。不能把通用视频封面误称为重点时间点截图。

## 3. 用户体验与验收标准

### 3.1 标签页行为

1. 用户在标签页 A 的 YouTube 视频页点击“分析此视频”。
2. 扩展只为标签页 A 启用 Side Panel。
3. 用户切换到任何其他网页标签页时，扩展的 Side Panel 不显示。
4. 用户回到标签页 A 时，面板恢复任务进度或分析结果。
5. 后端任务在用户离开标签页 A 后继续执行。
6. 用户打开另一条 YouTube 视频时，扩展不自动创建任务，必须主动点击分析。

### 3.2 字幕可用性判定

视频满足以下全部条件才进入分析：

1. 能列出至少一个字幕轨道。
2. 选中的轨道能被实际读取。
3. 返回至少一条带起止时间的字幕片段。

前端状态：

| 条件 | 展示文案 | 是否可分析 |
|---|---|---|
| 人工字幕可读 | “提供者字幕” | 是 |
| 仅自动字幕可读 | “YouTube 自动字幕” | 是 |
| 没有轨道或字幕为空 | “该视频暂无可读取字幕” | 否 |
| 视频不可用或受限 | “当前无法读取该视频字幕” | 否 |
| 请求受限 | “字幕服务暂时不可用，请稍后重试” | 否 |

### 3.3 结果页

结果页按以下顺序呈现：

1. 视频标题、来源字幕语言、字幕类型、目标翻译语言和处理时间。
2. 一句话概览和 3 至 6 条摘要要点。
3. 章节列表。每章包含标题、开始时间、简短说明。
4. 重点片段卡片。每张卡包含时间范围、该片段结论、原文摘录、译文摘录和跳转按钮。
5. 可展开的完整逐字稿。每段显示时间、原文和译文。

点击任何时间点都使用 YouTube URL 的 `t` 参数或播放器消息跳到对应位置。MVP 不在扩展中重放或下载视频。

## 4. 选型

| 领域 | 选型 | 说明 |
|---|---|---|
| 扩展 | Manifest V3、React、TypeScript、Vite | Side Panel UI 与浏览器 API 边界清晰 |
| 标签页控制 | Chrome `sidePanel`、`tabs` API | 为发起分析的 `tabId` 启用面板，其他标签禁用 |
| API 服务 | Python 3.12、FastAPI、Pydantic | 与字幕库和异步任务集成直接 |
| 字幕获取 | `youtube-transcript-api` | 获取公开视频的人工字幕和自动字幕，并保留时间戳 |
| 翻译 | LibreTranslate，封装为 `TranslationProvider` | 内部测试可用；后续用 LLM Provider 替换实现 |
| 摘要与章节 | 支持结构化 JSON 输出的 LLM Provider | 输入带时间戳的译文，输出可追溯的章节和重点 |
| 异步任务 | Redis + Celery | 字幕、翻译、摘要分为可重试后台任务 |
| 数据库 | PostgreSQL | 保存视频、任务、字幕段、翻译、摘要和章节 |
| 可观测性 | Sentry、结构化日志 | 跟踪字幕失败、翻译失败、模型失败和任务耗时 |

LibreTranslate 在内部测试阶段可使用受控实例。公开共享实例只可用于临时手工验证，不能作为团队测试或上线环境的依赖，因为它没有稳定性和配额保证。

## 5. 系统架构

```text
Chrome Side Panel
  -> FastAPI: 创建与查询分析任务
  -> PostgreSQL: 读取缓存或写入任务状态
  -> Redis/Celery: 执行后台任务
       -> youtube-transcript-api: 列出并读取字幕
       -> LibreTranslate: 分段翻译
       -> LLM Provider: 摘要、章节、重点片段
  -> PostgreSQL: 保存最终结果
Chrome Side Panel <- FastAPI: 轮询任务状态和读取结果
```

扩展不直接读取或解析字幕，也不持有翻译、模型服务密钥。所有外部调用由后端完成。

## 6. 数据与接口设计

### 6.1 核心实体

| 实体 | 关键字段 |
|---|---|
| `videos` | `video_id`、标题、时长、来源 URL、创建时间 |
| `transcript_tracks` | `video_id`、语言代码、语言名、`is_generated`、可翻译标记 |
| `transcript_segments` | `track_id`、序号、`start_ms`、`duration_ms`、原文 |
| `translations` | `track_id`、目标语言、`provider`、字幕版本、译文 |
| `analysis_jobs` | `video_id`、源语言、目标语言、状态、失败码、创建和完成时间 |
| `analysis_results` | `job_id`、一句话概览、摘要 JSON、章节 JSON、重点 JSON、模型版本 |

字幕和译文必须分开保存。翻译缓存键为：

```text
videoId + sourceLanguage + targetLanguage + transcriptVersion + provider + providerVersion
```

### 6.2 API

| 方法 | 路径 | 行为 |
|---|---|---|
| `POST` | `/v1/videos/inspect` | 校验 URL，返回视频信息和可用字幕轨道 |
| `POST` | `/v1/analyses` | 传入视频 ID、源语言、目标语言，复用缓存或创建任务 |
| `GET` | `/v1/analyses/{jobId}` | 返回 `queued`、`processing`、`completed` 或 `failed` |
| `GET` | `/v1/analyses/{jobId}/result` | 仅在完成后返回结构化结果 |

创建任务的成功响应必须返回 `jobId` 和是否命中缓存。扩展每 2 秒轮询一次状态，完成或失败后停止轮询。

## 7. 翻译策略

`TranslationProvider` 是唯一的翻译调用边界：

```text
translate(segments, source_language, target_language) -> translated_segments
```

规则：

1. 按原始字幕段聚合请求，每批控制在 1,000 至 3,000 字符。
2. 译文返回后必须映射回原始段 ID，不能丢失时间戳。
3. 每批最多重试 3 次，采用指数退避；持续失败则将任务标记为 `translation_failed`。
4. 翻译失败时保留原文逐字稿，结果页显示原文可用、译文暂不可用。
5. 后续接入 LLM 时，只新增 `LlmTranslationProvider`，不修改 API、数据模型和前端结果结构。

摘要和章节生成使用独立的 `AnalysisProvider`，不与 LibreTranslate 耦合。模型必须输出 JSON，且每个章节和重点片段都包含 `start_ms`、`end_ms` 和基于字幕的文字说明。

## 8. 失败处理与安全

1. 对无字幕、字幕被禁用、视频不可用、请求受限分别记录机器可读失败码。
2. 任务最多执行一次字幕读取、三次翻译重试、两次 LLM 重试，防止死循环和额度失控。
3. 只记录分析所需的公开视频标识、字幕与结果，不保存用户浏览历史。
4. 后端验证 YouTube 视频 ID 和 URL 格式，拒绝任意 URL 抓取请求。
5. API 密钥只存在服务端环境变量，扩展中不得包含。
6. 通过每个匿名设备或账户的日分析次数限制，防止公共字幕和翻译服务被滥用。

## 9. 实施顺序

### 阶段 A：可读字幕与 Side Panel

1. 建立 Manifest V3 扩展、Side Panel、标签页激活监听和 YouTube 视频 ID 识别。
2. 建立 FastAPI、PostgreSQL、Redis、Celery 的本地开发环境。
3. 实现字幕轨道发现、真实读取校验和错误码映射。
4. 在指定 `tabId` 中显示分析入口、字幕语言选择和任务进度。

验收：在存在人工字幕、只存在自动字幕、无字幕的三条公开视频上分别得到正确状态；切换网页标签时面板不显示，切回发起任务的标签页时恢复。

### 阶段 B：翻译与结果缓存

1. 建立 `TranslationProvider` 和 LibreTranslate 实现。
2. 按批翻译、重试、保存字幕段译文，并使用缓存键去重。
3. 在面板展示原文、译文和翻译失败状态。

验收：同一视频和语言组合第二次分析不产生新的翻译请求；任一翻译批失败时，原文仍可查看。

### 阶段 C：摘要、章节与重点片段

1. 建立 `AnalysisProvider`，要求 JSON Schema 输出。
2. 基于译文及时间戳生成概览、摘要、章节和重点片段。
3. 在扩展中渲染章节与重点卡片，并实现 YouTube 时间跳转。

验收：每个章节和重点片段的时间范围存在于字幕时长内；点击时间可打开或定位到正确视频位置。

### 阶段 D：内部测试与替换准备

1. 记录 LibreTranslate 成功率、延迟和单视频字符数。
2. 测试英文、中文、日文字幕及人工/自动字幕组合。
3. 根据翻译质量、稳定性和成本决定是否加入 `LlmTranslationProvider`。

验收：能根据监控数据比较 LibreTranslate 与候选 LLM 翻译服务，切换 Provider 不改变 API 合约或既有结果页面。

## 10. 第二阶段

第二阶段在合规边界确认后增加 `yt-dlp + FFmpeg`：对允许处理的视频获取媒体，在重点时间点抽取真实视频帧，并将帧图、字幕摘录和译文并排展示。无公开字幕视频的 ASR 也在此阶段评估，不进入本 MVP。

## 11. 最终确认项

本方案确认以下决策：

1. MVP 仅支持存在可读取公开字幕的公开视频。
2. Side Panel 只显示在发起分析的 YouTube 标签页，切换其他网页时不显示。
3. 翻译使用 LibreTranslate，范围限于开发和内部测试。
4. 翻译模块以 Provider 方式抽象，后续可替换为 LLM 服务。
5. 摘要、章节和重点片段由独立的 LLM 分析服务生成。
6. 真实关键帧截图和无字幕转录推迟到第二阶段。
